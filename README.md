# 数据分析实验与数据应用服务平台

面向指标口径管理、分析实验设计、OLAP查询、数据看板构建与数据API发布的数据应用平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 数据审计：旧版文本迁移到版本化差异

历史审计记录只有一个自由文本「变更内容」。审计页现在按迁移批次把旧文本拆成
字段级差异（`field / before / after`），同时保留原文、操作人与对象引用：

- `POST /api/audit/migration-batches`：读取既有审计记录与
  `audit_operator_archive` 操作人归档明细后迁移；整批写在一个事务里，
  任一条失败整批回滚，失败批次的归档输入与流水线仍可查询。
- `GET /api/audit/migration-batches/{批次}/records`：按批次对照旧文本与新差异，
  逐条核对操作人、对象引用、差异结构和归档一致性。
- `POST /api/audit/migration-batches/{批次}/rollback`：回滚到旧版文本；
  已被后续批次接管的记录保留现状，操作人与操作引用不回退。
- `GET /api/audit?batch_id=&content_version=`、`GET /api/audit/{id}/diff`：
  列表与差异消费共用同一批次口径；未迁移记录只给解析预览，不写入差异。
- 相同请求指纹重复提交直接返回既有批次，只保留一份有效结果；冲突策略支持
  记录级「跳过已迁移记录」与批次级「存在冲突整批失败」。

新旧事件都写同一个差异结构，避免查询同时返回旧格式和新格式；迁移前记录
仍以「旧版文本」版本出现在列表和导出里，导出文件带 `源文本归档`、`迁移批次`
与 `差异检查` 列，来源可回溯。

审计迁移的回归测试：`cd backend && .venv/bin/python -m unittest tests.test_audit_migration`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
